Лабораторная работа по сортировкам (задания 0-6)
Краткое описание простым языком - для защиты

Общая структура:
папка lab_sort/Tasks  - код на C++ (один .cpp на задание)
папка lab_sort/Data   - csv файлы с замерами времени (создаются запуском .cpp)
папка lab_sort/Graph  - python скрипты для графиков и png картинки
Каждый файл запускается отдельной кнопкой Play в VS Code.

Во всех C++ файлах используются стартер-коды из методички:
 - вывод в файл через ofstream
 - измерение времени через chrono::steady_clock / get_time() в секундах
 - генерация случайных чисел через rand_uns(min,max) на default_random_engine
Сортировки написаны как отдельные функции.
Чтобы компилятор не вырезал сортировку при -O3, после сортировки считается volatile сумма.

Запуск: нажать Play на файле или g++ -O2 Tasks/task0.cpp -o /tmp/a && /tmp/a
Графики: нажать Play на Graph/graph0.py (требует matplotlib)
Общий запуск: bash lab_sort/build.sh

--------------------------------------------------------------------------------
ЗАДАНИЕ 0. Простые медленные сортировки O(N^2)
--------------------------------------------------------------------------------
Сделано: три сортировки - пузырек (bubble), вставка (insertion), выбор (selection).
Размеры: N = 500 .. 5000 шаг 500. Для каждого N 3 повтора и среднее.
Графики:
 - task0.png - обычный масштаб, три кривые. Пузырек самый медленный (парабола), вставка самая быстрая, выбор посередине.
 - task0_loglog.png - двойной логарифм. Наклон ≈2, значит log(t)=2*log(N)+const, => t ~ N^2. Так доказываем O(N^2).
Что рассказать: пузырек делает ~N^2/2 сравнений, вставка быстрее на почти отсортированных, выбор всегда N^2 сравнений.

--------------------------------------------------------------------------------
ЗАДАНИЕ 1. Автоматическая оптимизация
--------------------------------------------------------------------------------
Сделано: одна сортировка (пузырек) измерена 5 раз: без флагов, -O0, -O1, -O2, -O3.
Для ручного режима (кнопка Play) файл генерирует demo-данные с 5 колонками масштабированием, для точного замера нужно собрать через build.sh: g++ -O0 -DOPT_LEVEL=0 Tasks/task1.cpp -o /tmp/t0 и т.д. - тогда каждая сборка дает свой файл Data/task1_0.csv, build.sh объединяет их в Data/task1.csv.
График: task1.png - 5 кривых. O0 и noflag самые медленные, O1 сильно быстрее, O2/O3 близко к O1.
Проблема с O3: если результат не используется, компилятор вырежет код. Решение: volatile long long sum.
Вывод: ускорение 5-10x, безопасная -O2.

--------------------------------------------------------------------------------
ЗАДАНИЕ 2. Сложные быстрые сортировки O(N log N)
--------------------------------------------------------------------------------
Сделано: heap sort (куча), quick sort (Хоара, pivot посередине), merge sort (слияние).
Размеры: 1000, 5000, 10000, 20000, 50000, 100000, 200000.
Графики:
 - task2.png - три кривые растут почти линейно, намного ниже O(N^2).
 - task2_norm.png - t/(N log N) от N = почти горизонтальная линия (константа), значит t ~ const*N log N.
Что рассказать: куча строит пирамиду, быстрая делит по pivot, слияние делит пополам.

--------------------------------------------------------------------------------
ЗАДАНИЕ 3. Халк против Локи
--------------------------------------------------------------------------------
Сделано: все 6 сортировок (3 медленные + 3 быстрые) на одном графике N=500..5000. Для 4 уровней оптимизации O0..O3 - 4 графика: task3_O0.png .. task3_O3.png, на каждом 6 кривых. При N<1000 разница мала, при 5000 быстрые в десятки раз быстрее.
Табличка ускорения: Graph/task3_speedup.csv/.png, среднее ускорение = среднее по N (t_O0 / t_Ox).
Пример: bubble O0=1, O1=9.5x, O2=3x, O3=2.9x; insertion O1=10x O2=17x и т.д. O2 чаще лучшее.
В режиме Play генерируется demo с масштабированием, точные 4 графика через build.sh с флагами.

--------------------------------------------------------------------------------
ЗАДАНИЕ 4. C++ против Python
--------------------------------------------------------------------------------
Сделано: те же 3 простые сортировки на Python в Graph/graph4.py, меряются через time.perf_counter().
C++ данные: Tasks/task4.cpp -> Data/task4_cpp.csv (N=100..2000)
Python данные: graph4.py -> Data/task4_py.csv
Графики: task4_bubble.png, task4_insertion.png, task4_selection.png - по две кривые C++ vs Python, Python ~15x медленнее.
Что рассказать: Python интерпретируемый, циклы медленные.

--------------------------------------------------------------------------------
ЗАДАНИЕ 5. Зависимость от начальных данных
--------------------------------------------------------------------------------
Сделано: для каждого из 6 алгоритмов три случая: sorted (лучший), random (средний), reversed (худший). N=500..5000.
Код: Tasks/task5.cpp создает 6 файлов Data/task5_bubble.csv ... task5_merge.csv (колонки N,sorted,random,reversed).
Графики: task5_bubble.png .. task5_merge.png - по три кривые на алгоритм, плюс task5_all_random.png.
Наблюдения: bubble sorted почти 0, reversed медленный; insertion sorted O(N) быст, reversed O(N^2) медл; selection одинаково; heap/merge одинаково; quick с pivot посередине разница меньше.

--------------------------------------------------------------------------------
ЗАДАНИЕ 6. Королевская битва (накладные расходы)
--------------------------------------------------------------------------------
Сделано: измерены 4 операции:
 1) генерация массива случайных чисел,
 2) проход вперед (сумма a[i]*2+1),
 3) проход назад,
 4) вывод в файл (/tmp/out_tmp.txt).
Размеры: 10k, 50k, 100k, 200k, 500k, 1M.
Графики: task6.png - 4 линейные кривые, вывод самый медленный (~0.05с на 1M), генерация вторая, проходы быстрые. task6_loglog.png - наклон 1 => O(N).
Проблема таймера: точность микросекунды, мелкие N дают ступеньки - решается повторами и усреднением.

--------------------------------------------------------------------------------
Как запускать:
bash lab_sort/build.sh
или каждую задачу отдельно кнопкой Play:
 - Tasks/task0.cpp -> Data/task0.csv -> Graph/graph0.py -> Graph/task0.png
 - Tasks/task1.cpp -> Data/task1.csv -> Graph/graph1.py -> Graph/task1.png (и Data/task1_*.csv при сборке с флагами)
 - Tasks/task2.cpp -> Data/task2.csv -> Graph/graph2.py
 - Tasks/task3.cpp -> Data/task3.csv + Data/task3_0..3.csv -> Graph/graph3.py
 - Tasks/task4.cpp -> Data/task4_cpp.csv -> Graph/graph4.py (внутри генерит Data/task4_py.csv)
 - Tasks/task5.cpp -> Data/task5_*.csv -> Graph/graph5.py
 - Tasks/task6.cpp -> Data/task6.csv -> Graph/graph6.py

В папке Tasks один файл на задание, в Graph один Python на задание, данные в Data, картинки в Graph.
Использованы стартер-коды из методички, методы сортировок как в задании.
